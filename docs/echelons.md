# 海岸多梯队任务

`shore-echelons-v1` 是第21个内置场景：18台设备、9项任务，复用原有空中／地面／水面、通行、通信、能源、材料和移动中继组件。

| 任务梯队 | 实际流程 |
| --- | --- |
| 前出准备 | 空中侦察后，水域勘察与岸线引导点标定并行；水域勘察完成后部署岸线通信中继 |
| 岸上处置 | 引导与中继部署均完成后，确认需求、取货运输、设施维修 |
| 通道复查 | 水面复查后执行空中复核 |

引导点标定使用到场勘测作业和完成事件，不模拟物理伴航。中继由真实地面设备移动、部署并驻留，消耗1套材料；保留1台备用车。部署记录保存实际停驻坐标，沿用4单位任务作业半径，不能把任务点误作设备精确停点。驻留设备用于显式点对点路由，不会自动替中央报告转发。

## 可选场景字段

```json
{"echelons":[
  {"id":"advance","name":"前出准备梯队","taskIds":["inspect","sea-survey","guide-shore","deploy-shore"]},
  {"id":"support","name":"岸上处置梯队","taskIds":["confirm","deliver","repair"]},
  {"id":"review","name":"通道复查梯队","taskIds":["sea-review","verify"]}
]}
```

支持1～8组，每组具备唯一ID、最多100个UTF-16单元的名称及非空任务ID列表。初始任务必须各归一组，不能重复、遗漏或引用未知任务；任务前置只能来自同组或声明顺序更早的组。原有任务图还独立检查缺失引用与循环，JS与Rust初始化分别校验这些约束。

这是任务组织元数据，保存在 `session.scene` 和 `archive.config.scene`，不增加世界快照根字段或单体观察字段。设备可以被不同梯队任务复用，卡片中的执行设备是当前记录，并不代表固定编组或编队控制。真正的执行条件仍是 `dependsOn`、能力、资源、能源、路线和动作校验；分组不授予协调器权限，也不会替任务增加隐含的整组屏障。省略字段时旧场景与协议继续工作。

## 任务页

在场景设置中选择“海岸多梯队协同”，打开任务页。卡片使用当前显示帧统计完成、活动／待启动、就绪和在途数量，列出跨组前置及已记录执行设备。选择卡片只筛选任务，不提交世界命令；跳转跨组前置任务会清除分组筛选。动态追加而未在初始配置分组的任务单独列出。

视图只有在场景ID和初始任务的不可变内容与显示帧匹配时才采用分组。对象键顺序不参与语义比较，原生JSON与JS可以使用不同字段顺序。历史不会借用未来完成进度或未来设备记录；单体视图不会读取全局任务分组，即使输入混入额外元数据也不显示。

## 稳定的最近优先

新场景种子7出现两台车到目标的数学等距：位移 `[15,-5]` 与 `[-9,-13]` 的平方距离均为250。JS与Rust的 `hypot` 舍入曾让其选择不同设备。最近优先现在在两端比较 `dx*dx + dy*dy`，相同时沿用原有设备ID规则；电量优先不变。坐标仍使用原有地图范围与物理精度，没有把视觉位置写回世界，也没有对轨迹或能耗进行取整。

## 运行

```sh
BOX_PHYSICS_BACKEND=rust BOX_TASK_BACKEND=rust BOX_COMM_BACKEND=rust BOX_NAV_BACKEND=rust node server/world-server.js
python3 sdk/python/multi_agent_demo.py --scene shore-echelons-v1 --physics rapier --sensor-mode rapier --fault none --dispatch networked_reported --link-profile long --clock step --coordinators 2 --archive
python3 sdk/python/multi_agent_demo.py --schedule-plan examples/experiments/shore-echelon-recovery.json --sensor-mode rapier --fault none --dispatch networked_reported --link-profile long --clock step --coordinators 2 --coordinator-fault-tick 50 --archive
npm run test:echelons
```

独立运行含18个设备进程和2个具名协调器。组合计划复用北／南海况区，在T45使巡查艇模拟链路中断20步，在T50退出第一个指挥节点。节点接管、材料、任务依赖与物理恢复按实际记录判断，不由分组标签推断。设备本机RPC仍不经过模拟链路，案例不代表完整无线电网络。

内存历史有字节上限，报告可能明确标记为部分记录。完整回放应来自同次运行的持久快照日志，并保留原始报告的截断标记；不能把不同记录拼成一次运行。示例使用固定步进，不是实时性能承诺。

后续进度已增加 [海岸救援模板](shore-rescue.md)、[指挥节点视图](coordinator-nodes.md) 和 [计划审阅](plan-review.md) 的代码与数据验证。更多人工接管／失联组合、三场景Beta的平台及视觉验收仍未完成；梯队卡、筛选、节点与计划控件需手动解锁Mac后实机检查。
