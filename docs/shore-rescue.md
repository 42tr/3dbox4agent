# 海岸中继协同救援

第22个内置场景 `shore-rescue-v1` 复用多梯队场景的18台设备、9项任务和3组任务组织。三台地面维修设备增加 `rescue: {workTicks: 6}` 与 `rescue` 能力，两台地面中继车配置 `recoverableFault: true`；其余场景组件、任务依赖、耗材与通行规则保持一致。

部署任务消耗唯一套件并产生驻留中继。管理员可在部署完成后注入带期望故障代次的故障。维修设备必须先用自身传感器取得故障目标及观测步，再接近4单位内持续作业6步。机械复位保留目标的位置、电量、部署任务、分配代次和驻留位置；不会重新消耗套件。救援作业本身消耗维修设备0.48电量，接近过程另计移动能耗。此配置没有氧气、拖曳、充电救援或物理货物接力。

## 网页操作

在“场景与世界设置”选择“海岸中继协同救援”并新建运行。中继部署后，可在故障控制选择该中继并注入故障。选择已观测到目标的维修设备，在设备操作中执行现场救援；距离不足时先接近，再提交救援。设备进程启动面板可为有工具的维修设备选择巡查救援。巡查默认关闭，自动救援只读取该设备的观察与记忆。

任务页的4／3／2梯队统计仍描述任务状态。中继部署任务已经完成后发生故障，不会倒退该任务；应另查看设备故障与救援记录。驻留中继恢复后可用于显式指定的设备消息路径，中央状态上报不会自动改走它。

## 独立进程运行

服务应启用Rust物理、任务、通信与寻路后端；下列命令假设服务位于8787端口。

```sh
PYTHONPATH=sdk/python python3 sdk/python/multi_agent_demo.py \
  --scene shore-rescue-v1 --physics rapier --sensor-mode rapier \
  --fault resident --dispatch networked_reported --link-profile long \
  --clock step --coordinators 2 --auto-rescue --archive --timeout 180 \
  > shore-rescue.json
```

`--fault resident` 等到真实部署完成再注入故障。去掉 `--auto-rescue` 可运行负对照：即便9项任务完成，驻留中继未复位时仍报告 `failed / resident_fault_not_recovered`，进程退出码为1。

在自动救援命令追加 `--rescue-search --coordinator-fault-tick 50`，可组合局部巡查与指挥节点失效。巡查只使用自身位置、有限搜索点和传感器，不获得管理员故障坐标或全局地图。指挥节点失效测试由编排进程重新分配分片和凭据；设备救援仍由各自进程执行。

## 本轮记录

- `tests/shore-rescue-world.test.js` 覆盖两种物理模式、三种寻路指标，分别启用与关闭自身观察救援，共12组、1,692帧JS／原生精确比较。所有组完成9项任务，6个救援组分别复位一次，6个负对照均保留故障。设备位置、目标电量、驻留身份、唯一套件、单体protobuf观察、地表合法性与回放校验通过。
- 实际18个设备进程及双指挥节点、原生Rapier／射线服务：无救援与自动救援均T245完成9项任务；前者正确报告恢复失败，后者由 `robot-2` 在T139复位T96发生的故障。巡查加T50指挥失效组合T288完成9项任务，`robot-3` 在T124复位，存活指挥接管分片。该组包含一次有意的进程终止，不能称所有子进程正常退出。
- 三份原始内存报告分别只保留186／183／140帧，均明确标注部分历史。各自同次运行的持久哈希链另行导出完整274／276／354帧并校验；原报告未修改，档案未拼接。
- 原21个场景定义及84个旧JS／当前JS／原生初始世界比较一致。Rust、协议与物理二进制未改变。相关回归由 `npm run test:shore-rescue` 执行，UI／TypeScript另验。本轮没有重复宣称进度303的298项完整主链、175项完整原生链为当前版本全量结果。
