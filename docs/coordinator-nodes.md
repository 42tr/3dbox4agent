# 指挥节点视图与凭据管理

主控制台增加“指挥节点”页。它按当前显示快照汇总外部指挥入口：已接受分配、在途、拒绝／失败、提案、撤回、最近记录和当前分配来源。每项当前分配必须匹配其分配版本的 `task_assigned` 与紧随的 `decision_accepted` 记录；同一步内撤回并重新分给同一设备时，不会把旧指令当作新分配的来源。缺少匹配记录时明确计入未归属数量。

未具名的默认协调者和管理员指挥请求共用未命名入口，现有记录无法区分两者。规则自动分配不会伪装成外部指挥节点。最多显示32个入口和最近100条记录，截取数量有说明。单体视图不读取全局指挥记录。

导入多进程报告时，节点故障、检测和分片接管记录按快照步以及报告中的观察版本过滤。同一步的较早版本不会显示有明确较晚观察版本的记录；旧报告只有仿真步时仍标明该限制。这些是外部管理进程提交的未认证记录，保留来源标识，不能据此证明真实进程状态。

## 当前凭据名单

节点页的“当前凭据名单”打开管理面板，也可通过 `#command-nodes` 定位。连接本地世界服务后，管理员手动刷新名单，可查看具名节点标识和默认协调者是否已签发凭据。名单有独立的凭据版本及读取时的仿真步、世界版本；读取不会推进世界或写入回放。

凭据有效只表示该凭据可以访问接口。服务没有采集外部Python进程的心跳，页面始终将其运行状态标为未知。导入回放、历史、单体和只读观察不提供当前凭据管理，避免把实时名单混入历史快照。

在刷新后填写节点标识、规划器分片数和从0开始的分片索引，可签发或轮换具名规划器命令。节点标识为1–40位字母、数字、下划线或短横线，分片数1–16，索引小于分片数。再次签发同名凭据会使旧凭据失效。含凭据的命令仅留在该管理组件中，默认折叠，并可复制、清除；不会放入共享世界状态或导出档案。

所有具名协调者共享有限的指挥观察，不能读取全局世界或管理凭据。分片是规划器约定，不是服务器按任务划分的权限。运行多个规划器时使用相同分片数与不同索引，并切换到相应外部指挥模式。

撤销凭据使后续请求失效，既有接受分配和已排队指令仍按世界规则处理。要撤回任务，应使用“任务指挥”的撤回入口。凭据签发／撤销后需刷新名单，再进行下一次管理操作。响应丢失时页面不会自动重试，必须先核对名单；需要新命令时可显式轮换。

## 管理接口

`GET /sessions/:sessionId/coordinators` 仅接受管理员凭据，返回：

```json
{
  "version": 1,
  "sessionId": "example-session",
  "rosterRevision": 3,
  "worldRevision": 24,
  "tick": 18,
  "legacyCredentialActive": false,
  "named": [{"id": "node-1"}, {"id": "node-2"}]
}
```

它不返回令牌、密钥摘要、全局设备或进程在线状态。现有 `POST/DELETE /sessions/:sessionId/coordinators/:id/credentials` 新增可选请求字段 `expectedRosterRevision`，版本不符返回409 `coordinator_roster_changed`，不会修改凭据。成功响应新增 `rosterRevision`。已有不传该字段的SDK保留原行为；网页始终携带读取的版本。默认协调者轮换也使名单版本递增。

名单和凭据版本是会话管理状态，不属于物理世界、单体／指挥观察、历史快照或持久世界回放。日志分支保留原指挥来源记录，重新开始空的凭据名单与版本0，旧会话凭据不能访问分支。

## 本轮验证

- 两种物理模式、三种外部指挥模式共6组真实JS／原生比较，核对即时／在途／接受、提案、撤回、精确分配版本、同一步人工重分配与历史帧；单体输入用会抛错的全局属性验证不读取越界数据。
- 实际原生HTTP测试覆盖管理员／只读／设备／具名角色、版本冲突、旧SDK请求、轮换、撤销、令牌不泄漏、分支凭据隔离，以及真实提交后丢响应时的前端控制器行为。单个真实Python具名规划器另在无丢包、长距离配置中完成9项自动执行任务。
- 当前原生Rapier／射线服务运行18个设备进程与双指挥节点，固定步、延迟报告、T50节点失效接管及驻留中继巡查救援组合，在T288完成9项任务。当前节点视图识别 `node-1` 接受1项、`node-2` 接受8项，另保留1次拒绝记录。21份进程生命周期日志含一次有意终止与受控停止，不能称全部正常退出。
- 原始内存报告仍是139帧部分历史；同次持久哈希链另行验证完整354帧。当前视图还读取3份明确标记为历史304版的记录，共1,258帧逐项核对任务来源与管理记录边界。原报告未修改，记录未拼接。
- 最终10项相关回归、30项UI／类型命令和HTML构建使用相同的695份稳定输入。Rust、协议、物理二进制、世界引擎及22个场景定义未改。完整主链／原生链最近仍为303版的298／175项，本轮没有重新宣称全量通过。
