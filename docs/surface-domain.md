# 水陆空协同与水域通行

进度301把水域配置接入场景、合法出生、按设备类型寻路、原生完整世界步、单体观察、回放和前端呈现。`shore-surface-v1` 配置见 [海岸场景](../examples/scenes/shore-surface.json)：16台空中、地面和水面设备依次执行侦察、水域勘察、岸上确认、岸边取货、设施维修、水域复查及空中复核，共7个任务。这是同一套组件的组合。原来的 `shore-coordination-v1` 仍保留为抽象海岸原型。

## 地图与出生

场景可选字段 `surfaceDomain.water` 最多含16个矩形：

```json
{"surfaceDomain":{"water":[{"id":"sea","name":"水域","x":45,"y":0,"w":55,"h":100}]}}
```

矩形位于100×100地图内，水域为它们的并集，允许重叠、相接和围出陆地空洞。地面设备避开水域；`mobility: "water"` 的设备限制在水域内；空中设备不受水陆边界限制。水面类型必须配置水域。本版本只接受平面水域，不能与高度场同时启用。

设备类型可选 `spawnArea: {"x":52,"y":12,"w":40,"h":22}`。出生采样按2单位网格使用原有种子随机数，位置还必须满足障碍、水陆区域、地图留距和同高度设备间隔。省略该字段时保留旧采样顺序与规则。类型标签不能替代 `mobility`。建造、可部署地面中继及现有机械救援工具仍受各自的地面类型约束。

JS 与 Rust 使用同一套精确矩形排列，把水域并集或其补集作为相应设备的导航禁入区。区域内部的接缝不会产生墙，陆地空洞不会被漏掉。常规导航仍使用保守的2单位余量；实际 Rapier 代理是0.8半径球体、0.02控制器偏移，采用32位浮点。圆形碰撞体的合法位置检查允许1e-4数值余量，不把导航方形余量误作实际球体。闭合世界外围同样有通行边界。

## 移动、岸边交互与能耗

普通移动必须到达合法目标，不会自动把岸上坐标改成水上坐标。任务作业沿用4单位的平面交互距离；仅当目标不在设备通行区域内时，选择3.7单位范围内的合法接近点。充电使用2.8单位接近点，仍需进入原有3单位充电范围。候选点是12个固定方向，按实际导航目标函数选择可达路线；这不是任意几何下的全局交互姿态最优解。

运输取货后，后半段路径从真实取货接近点规划。路径重算、临时封闭等待与恢复、返程估计和能耗均使用设备自己的通行区域。既有速度／能耗区域也可用于水面通行成本；它们不代表真实流体。世界整步与混合后端均受约束，运动学模式也不能沿伪造路线跨岸。

水陆边界是运动约束，不是实体墙。原生视线与雷达忽略虚拟边界，建筑、岛礁简化碰撞体和临时封闭仍会遮挡。完整原生绑定核对环境配置、设备类型、实际边界形状与碰撞实例；不能把另一份水域几何与当前环境混用。检查点和异常回滚保留这些形状与筛选标识。

## 单体分步与 SDK

单体分步观察保留物理任务点 `assignedTasks[].waypoint`；必要时另给出可选 `approachPoint`。它只根据本机位置、授权任务和静态公开地图计算，不使用实时封闭或扰动。`withinReach` 始终按原物理任务点检查，接近点不能代替作业结果。HTTP、gRPC、类型化观察和二进制流均保留该扩展字段；旧任务没有该字段。

更新后的 `task_agent.py` 和页面“填入合法接近点”优先使用此点。显式 `null` 表示暂未提供，不回退到非法的物理坐标。界面仍需由用户提交移动意图，服务器会在执行时重新校验。单体观察不增加全局水域地图或其他设备任务。

```sh
python3 sdk/python/multi_agent_demo.py --scene shore-surface-v1 --physics rapier --sensor-mode rapier --fault none --dispatch networked_reported --link-profile long --clock step --archive
python3 sdk/python/multi_agent_demo.py --schedule-plan examples/experiments/shore-energy.json --sensor-mode rapier --fault none --dispatch networked_reported --link-profile long --clock step --auto-charge --preempt-for-charge --archive
```

第一条运行16个设备进程与1个指挥进程；第二条在T+10降低巡查艇电量并临时封闭岸边通道，启用既有的本机返程估计补能策略。两个补能选项默认关闭。此处使用同步步进，不是实时吞吐或分布式无线网络性能测试。中央任务状态与本地设备 RPC 仍不经过模拟链路；延迟状态与指挥下发使用原有抽象通信模型。

## 回放与呈现

回放绑定原始水域配置、设备类型、合法位置及路线。活动任务／动作分支保留这些约束和单体授权。三维与二维使用同一份水域并集；船体来自 [Kenney Pirate Kit](https://kenney.nl/assets/pirate-kit) 的 CC0 模型，镜像地址、原始字节摘要和许可证保存在 `assets/mission-control/kenney-pirate-kit/`。呈现隐藏船桨、归中并缩放船体，船体网格不替代简化物理代理。

代码与离线几何检查不能替代浏览器验收。当前 Chrome 工具仍受 Mac 锁定影响，水面画面、交互和控制台尚待实际检查。月面默认界面继续沿用 `640.png` 方向。

新增 [海况与通航演练](sea-state.md) 通过同一通行代价组件提供可恢复的航速／能耗扰动；不是流体模型。

本版本没有浮力、波浪、潮汐、方向性水流、两栖切换、真实港口装卸、跨平台物资接力或完整多梯队指挥，也没有新增氧气与设施供电模型。完整 M4／M5／M6 和最终视觉、平台验收仍未完成。
