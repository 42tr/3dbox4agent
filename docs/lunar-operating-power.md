# 月面基础运行耗电

世界设置中的“月面基础运行耗电”（`lunar-power-v1`）沿用救援场景的 15 台设备与 11 项任务，增加可选的基础电气负载。场景 JSON 示例为 `examples/scenes/lunar-power.json`。中继每步消耗 0.4，其他设备每步消耗 0.01，单位仍是 0–100 的抽象电量。

自定义设备类型可配置 `operatingEnergyPerTick`，范围 0.001–5。省略时不增加基础耗电，也不增加对应快照和观察字段；原有 17 个场景保持原配置。配置随场景与日志分支继承，运行中不能通过设备动作修改。

每个实际推进的仿真步，在时间与地图变更之后、通信和动作执行之前扣除一次负载。空闲、作业、移动、补能及热保护中的可用设备均会扣电；机械故障或已退出设备不扣电。暂停和同一仿真步内的管理操作不扣电。热控仍计算移动和作业产生的热量，本版本没有给基础电气负载增加独立热源，也没有电子设备分系统。

本机观察的 `self.operatingEnergyPerTick` 是配置；`self.operatingState` 包含累计 `energySpent` 与已结算的 `tick`。其他设备的感知接触不暴露这些私有字段。全局指标 `operatingEnergy` 列出累计总量及各设备分项；已有运行能耗包含这笔电池支出，不能再次把分项加到总能耗上。HTTP、gRPC、类型化观察、二进制 v2 流和回放均保存相同字段。

回放可省略同一仿真步内的管理快照，保留的事件前缀用于解释扣电前的低电量注入或机械故障。相邻步按浮点精度校验实际扣电，避免累计量变大后放宽为百分比误差；较长的跳帧检查累计上限，不把稀疏快照当作逐步执行证明。

电量耗尽会产生 `energy_depleted`、`source: operating` 事件，终止该设备的待执行或正在执行动作，释放任务与材料预留，并把实际运输的备件留在设备当前位置。有活动任务时记录一次任务重规划；空闲或驻留设备不会制造任务重规划。此过程不增加机械故障次数或故障代次，现场机械复位不能恢复零电量设备。救援设备在作业中耗尽电量时也会失败，目标保持故障状态。

已部署中继保留部署位置、部署标识和套件消耗记录。电量降到既有转发下限 5 或以下即停止转发；此后仍扣基础负载，直到电量为零退出。扣电先于消息处理，因而恰在这一仿真步跌破下限的中继不能转发到期消息。任务链完成不等于中继网络持续可用；新场景中任务完成后可能存在已耗尽的中继。

仓库补能仍是每步补入 2。扣除基础负载后可能净增、持平或净减；负载达到 2 的设备不会被结束判定当作可通过补能恢复的候选。返程估算在静态已知地图的移动能耗上，加上预计行进步数乘基础负载；它不预测碰撞排队或未发布扰动。Python 设备进程与巡查策略也把指令提前步数中的基础负载加入原有补能预留计算，仍保留现有阈值上限，属于有界启发式策略。现有能耗优先寻路的路线排序没有改为全局总电耗最优。

可使用独立设备进程运行示例：

```sh
python3 sdk/python/multi_agent_demo.py --url http://127.0.0.1:8787 \
  --scene-file examples/scenes/lunar-power.json --physics rapier \
  --sensor-mode rapier --dispatch external --clock step --fault none --archive
```

电源库存、供电网络、零电量补给／拖曳、独立电子热源和氧气系统仍未实现。此阶段不构成完整月面生存保障或任务连续性模型。
