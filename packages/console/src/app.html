Rust 地面导航
可选 Rust 导航执行二维网格寻路、地表时间／能耗积分与路线简化，用于地面任务、充电、扰动和拥堵绕行；Node 准备障碍与区域，复查返回路径后提交。沿用 2 单位网格与障碍留距，不保证连续空间最优，也未增加地形高度。服务端连接状态会标记 Rust 导航；浏览器预览继续使用 JavaScript，不保证两种后端逐帧相同。
可选 Rust 任务内核检查分配、撤回及动作启动条件，计算作业和扫描进度、耗电、充电排队、装卸和完成效果，以及地表边界、移动距离预算、按实际位移扣减的电量、出界限制与风险区穿越，并判断扰动到期、任务截止及每步结束时继续、完成、等待补能或道路恢复以及无法继续；兼容的原生组件直接从本世界状态生成设备局部观察及静态地图返程电量估算，只返回该设备的动作、收件箱、证据与记忆；指挥观察直接从本世界原生状态生成任务候选、报告时效和指令记录；失败后优先保留最后提交的原生观察。完整原生后端将本步活动统计、执行中任务的移动／作业、拥堵恢复和途中耗尽合并提交；后续任务或事件拒绝时整批不生效。已接受动作的移动、扫描、补能排队及任务接续也按原顺序在原生批次内共同提交，使用实际地图、资源和物理射线；较晚动作失败不会留下前面动作的修改。物理移动跨越极近地表边界时按实际位移计费，避免微小步长停滞。完整原生服务由 Rust 按既有顺序推进整个固定步，包含分配后的中间感知刷新；运行环境标记 worldAdvanceVersion: 1。混合后端仍使用阶段适配。运动预算和能耗计算使用数值接口，减少每段运动的 JSON 转换；其他规则仍可能通过 JSON 传递。可选 Rust 通信后端处理设备消息的带宽排队、逐跳中继和投递，也判断中央指令、状态及证据报告的等待、送达与失败；中央链路不计算点对点距离、遮挡和带宽。完整原生路径由 Rust 读取几何遮挡并提交传输及事件；混合后端继续使用宿主适配。设备消息队列、收件箱、发送配额、去重及中断状态由 Rust 存储提交。中央状态、固定传感器、扫描证据及采样报告由 Rust 保存队列、终态与接收缓存。中央任务指令／决策也可由 Rust 保存身份、队列及终态；同时启用原生任务与通信时，用实际地图计算接令路线并一起提交分配与事件；完整原生固定步直接选择候选，混合后端沿用宿主阶段编排。备件及设施状态也可由原生资源组件持有，按任务代次提交预留、运输、维修与复核。其他世界对象及流程仍由 Node 维护；仿真时钟、终态、事件历史、任务图、完整设备状态和动作队列由所选 Rust 状态组件持有，运行时分别标记。单次世界步发生异常时，该会话停止并显示最后一次成功快照，设备和指挥者会收到失败标记，其他会话继续运行；测试覆盖 Rapier 已移动后 Rust 规则失败的情况。连接服务前选择 Rapier 仿真及 Rust 射线感知，可让设备观察、扫描动作和固定传感器使用物理射线；通信遮挡仍使用几何模型。默认感知方式不变。射线使用简化碰撞体和单精度，边界附近可能与几何判定不同。在线预览不运行本机物理后端。
